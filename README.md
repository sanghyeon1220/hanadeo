# 모바일 앱으로 설치하기 (PWA)

하나더는 **휴대폰 홈 화면에 설치하는 앱(PWA)** 으로 동작합니다. 설치하면 주소창 없이 전체 화면으로 열리고, 인터넷이 끊겨도 앱 화면이 열립니다(상품·거래 데이터는 연결되어 있어야 불러옵니다).

**설치 조건:** `https://` 주소로 배포되어 있어야 합니다(예: Vercel). `npm run dev`(개발 서버)에서는 앱 화면 저장 기능(서비스 워커)을 일부러 끕니다.

| 휴대폰 | 설치 방법 |
|---|---|
| 안드로이드 (크롬) | 사이트 상단의 **앱 설치** 버튼 → 설치. 또는 크롬 메뉴 ⋮ → 홈 화면에 추가 |
| 아이폰 (사파리) | **앱 설치** 버튼을 누르면 안내가 뜹니다. 사파리 **공유** → **홈 화면에 추가** → 추가 |

**관련 파일**
- `public/manifest.webmanifest`: 앱 이름, 아이콘, 색, 홈 화면 바로가기(상품 나누기·구매 요청)
- `public/sw.js`: 앱 화면을 기기에 저장(오프라인 실행). Supabase 데이터는 저장하지 않음. 앱을 고친 뒤 배포할 때 `VERSION` 값을 바꾸면 사용자 기기의 옛 화면이 교체됩니다.
- `public/icons/`: 앱 아이콘(일반·안드로이드 모양 맞춤용·아이폰용)
- `src/main.jsx`: 배포 환경에서만 서비스 워커 등록
- `src/App.jsx`: 하단 탭바, 앱 설치 버튼(`useInstallPrompt`), 아이폰 설치 안내

**모바일 화면:** 폭 760px 이하에서는 상단 메뉴 대신 하단 탭바(홈·시연·나누기·요청·내 거래)를 쓰고, 노치·홈 바 영역을 피해 배치합니다. 입력칸 글씨는 16px로 해서 아이폰에서 확대되지 않게 했습니다.

**검증:** 로컬 https 대신 `localhost`(브라우저가 안전한 주소로 취급)에서 안드로이드(Pixel 7) 환경으로 확인했습니다. 크롬 설치 가능성 검사 오류 0개, 서비스 워커 동작, 오프라인 재실행, 하단 탭 이동, 설치 버튼, 아이폰 안내 시트를 확인했습니다. 실제 휴대폰에는 설치해 보지 못했습니다.

**앱스토어(구글 플레이·앱스토어)에 올리려면:** 이 웹앱을 Capacitor로 감싸 Android Studio·Xcode에서 빌드하는 방법이 있습니다. 이 저장소에는 아직 포함하지 않았습니다.

# 발표용 20상품 시연 버전 사용법

**권장: 발표에서는 먼저 `발표시연_오프라인.html`을 더블클릭해 실행하세요.** 인터넷·로그인·Node.js가 없어도 열 수 있는 백업 시연판입니다. 실제 Supabase와 연결되지는 않습니다.

React 앱에서는 `npm install` → `npm run dev` 후 상단 메뉴의 **발표 시연**을 클릭하면 같은 조건 비교 시나리오가 보입니다. 이 화면은 Supabase 연결 여부와 무관하게 **체험 모드의 가상 상품 20개**를 사용합니다. 새로고침할 때 상대 날짜를 재계산하므로 유통기한이 지난 상태로 저장되지 않습니다.

- 가상 판매글: 콜라 6개, 우유 4개, 컵라면 4개, 다른 상품 6개 = 총 20개. 모두 별도 가상 판매자이며 실제 회원 계정은 생성하지 않습니다.
- 화면에서 `시나리오 1 — 콜라 500mL`를 선택하면 전체 20개 → 동일상품 6개 → 2,000원 예산 통과 5개 → 점수순 추천이 표시됩니다.
- 희망 만남 장소를 `역 출입구 앞`으로 변경해 보면 추천 1위 판매자가 바뀌는 것을 설명하기 좋습니다.
- `거래 시간`과 `예산`을 바꾸어 후보가 왜 줄어드는지 확인합니다.
- `이 조건으로 매칭·예약 시연` 버튼을 누르면 React의 기존 체험 모드에서 상품 카드/예약 플로우를 수행할 수 있습니다. 체험 모드의 데이터는 새로고침 시 초기화되며 실제 데이터베이스에는 기록되지 않습니다.
- 발표 전 `상품 20개 초기화`를 클릭해 거래 상태를 정리하세요.
- **중요:** 이것은 가중합 기반 개별 구매자 추천이며, 다대다 전체 최적 할당(헝가리안 알고리즘)을 구현한 단계는 아닙니다. 또한 한 구매자 기준 긴급도 점수는 모든 후보에 공통으로 더해지므로 순위를 바꾸지 않습니다.

매칭 알고리즘 기존 테스트 9개 + 발표 데이터 테스트 5개 = 총 14개가 통과했습니다. 독립 HTML은 Chromium 브라우저에서 시나리오 변경, 20행 표시, 위치 변경 1위 교체를 확인했습니다. 이 실행 환경에서는 React 패키지 설치가 완료되지 않아 새 React 화면의 실제 빌드/브라우저 구동 테스트는 못 했습니다.

# 하나더 — 1+1 나눔 매칭 웹앱 (React + Supabase)

**구현된 기능**: 회원가입/로그인(Supabase Auth), 상품 등록, 상품 사진(Storage), 구매 요청, 희망상품 일치 필터, 거리·가격·시간·긴급도 점수, 점수순 추천, 원자적 매칭 예약, 예약 취소, 거래 완료, 체험 모드.

> **2026-10-28 연동 업데이트:** 실제 Supabase 프로젝트의 4개 테이블, RLS 정책, 예약/취소 DB 함수, 이미지 버킷 생성을 완료했고 검증했습니다. `.env.local`에 해당 프로젝트 URL과 Publishable Key를 설정했습니다. 프런트엔드 호스팅 및 실제 계정으로 실행하는 통합 테스트는 아직 남았습니다.

## 1. 즉시 체험

## 2. Supabase 백엔드 구성 (이미 완료)

- 프로젝트: `kmbqwtnlyajxrymliqsx` (정상 운영 중)
- DB 테이블: `profiles`, `products`, `buyer_requests`, `matches` (모두 RLS 활성화)
- 서버 RPC: `reserve_match`, `change_match_status`
- Storage: `product-images` 버킷
- 보안 Advisor: 이번 검사에서 이슈 0개

- Supabase Dashboard의 `Authentication → URL Configuration`에서 개발 중에는 `http://localhost:5173`을 허용하고, 실제 배포한 주소가 생기면 추가하세요.

## 3. React 앱 실행

Node.js 20 이상을 권장합니다. 압축을 풀고 터미널에서 프로젝트 폴더로 이동합니다.

```bash
## .env.local 파일이 이미 설정되어 있어 이 단계는 건너뛰세요.
```

`.env.local`에 실제 Supabase URL과 브라우저 사용이 허용된 Publishable Key가 이미 입력되어 있습니다. 파일을 다른 사람에게 배포할 때는 프로젝트 접근 정책을 확인하세요.

```env
VITE_SUPABASE_URL=https://<YOUR_PROJECT_REF>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_<YOUR_PUBLIC_KEY>
```

그다음 다음 명령을 실행합니다.

```bash
npm install
npm run dev
```

터미널에 나타난 `http://localhost:5173` 주소를 브라우저에서 엽니다.

- 키가 설정돼 있지 않으면 앱이 **체험 모드**로 시작합니다.
- 두 키를 올바르게 설정하면 **실제 Supabase 연결 모드**로 시작합니다. 우측 상단에서 체험/실제 모드를 전환할 수 있습니다.
- 이메일 인증을 사용하는 경우 회원가입 후 인증 이메일을 확인하고 로그인합니다.

## 4. 처음 테스트할 흐름

1. 판매자 계정 A로 회원가입/로그인합니다.
2. `상품 나누기`에서 콜라 500mL, 2,200원, 최저가 900원, 적절한 유통기한과 거래 가능한 시간을 저장합니다.
3. 로그아웃 후 구매자 계정 B로 로그인합니다.
4. `구매 요청`에서 **같은 상품**, 2,000원 이상 예산, 겹치는 거래 시간, 만남 장소를 입력합니다.
5. `상품 둘러보기`에서 매칭점수를 확인합니다. 가격이 예산을 초과한 상품은 후보에서 제외됩니다.
6. `매칭 예약`을 누릅니다. 서버가 구매자 권한·상품 상태·가격·시간·중복 예약 여부를 다시 검증합니다.
7. `내 거래`에서 구매자 취소 또는 판매자 완료 기능을 테스트합니다.
8. 구매자 계정 C에서도 동일한 상품 예약을 시도해 **중복 예약 방지**를 확인합니다.

## 5. 매칭 알고리즘

상품이 먼저 일치해야 후보가 됩니다.

> ⚠️ 아래는 **v1 설명**입니다. 현재 식은 맨 위 업데이트와 `docs/MATCHING.md`를 보세요.

```text
(v1) 점수 = 100 × (0.35·거리적합도 + 0.30·가격적합도 + 0.20·시간적합도 + 0.15·긴급도)
```

- **거리**: Haversine 직선 거리로 계산. 1.5km 이상은 거리 점수 0.
- **가격**: 유통기한이 가까워질수록 초기 가격에서 최저가까지 선형으로 감소. 예산 초과는 후보 제외.
- **시간**: 겹치면 1, 겹치지 않으면 0.3. 다만 실제 **예약**은 시간이 겹쳐야 허용.
- **긴급도**: 1~5를 0.2~1.0으로 환산. 같은 구매자 안에서는 모든 후보에 같은 값을 더하므로 추천 **순위에 영향이 없습니다**. 다수 구매자 간 최적 배정 단계에서 의미가 커집니다.
- 거래 예약시 실제 가격과 점수는 PostgreSQL 서버 함수에서 다시 계산됩니다.

현재 구현은 **개별 구매자 추천**입니다. 구매자·판매자 전체에 대한 헝가리안 알고리즘/이진정수계획은 아직 구현하지 않았습니다.

## 6. 보안·데이터 설계

- `profiles`: 개인 닉네임 / 회원 ID (`auth.users` 참조)
- `products`: 상품 정보, 최저가, 유통기한, 공개 만남 장소 좌표
- `buyer_requests`: 구매 희망 상품, 예산, 긴급도, 거래시간, 공개 만남 장소 좌표
- `matches`: 예약자, 판매자, 매칭점수, 예약 당시 확정 가격, 예약 상태
- 모든 테이블에 RLS 정책이 적용됩니다. 구매 요청은 본인 및 실제 매칭된 판매자만 열람합니다.
- 일반 사용자는 `matches` 테이블에 직접 INSERT/UPDATE를 수행할 수 없습니다. `reserve_match`, `change_match_status` RPC가 서버 측 거래 처리 및 권한 검사를 수행합니다.
- 같은 상품 및 구매 요청의 활성 예약은 부분 UNIQUE INDEX가 차단합니다.
- 상품 사진 버킷은 공개입니다. 얼굴, 집 주소, 영수증 등 개인 정보가 있는 사진을 업로드하지 마세요.
- 예제 장소의 위경도는 **임의의 데모 좌표**입니다. 실제 출시 전 공개된 안전한 만남 장소로 교체하세요. 정확한 자택 위치 수집은 피하세요.

**출시 전 추가할 것:** 상품 카탈로그/바코드 API 연계, 신뢰도 및 신고/차단, 거래 채팅, 인증/정책 E2E 테스트, 이미지/텍스트 유해 콘텐츠 검증, 거래 시간대 검증, DB 마이그레이션, 운영 모니터링, 배포 환경 검증.

## 7. 로컬 테스트 및 빌드

```bash
npm test

```

- `npm test`는 Node.js 내장 테스트 러너로 핵심 매칭 함수 9개 사례를 검사합니다.
- 최종 다운로드 환경에서 의존성 설치와 `npm run build`는 다시 확인하세요. 프로젝트의 JSX 구문 분석과 매칭 로직의 9개 테스트는 별도로 통과했습니다.

## 8. 2026-10-28 상품 카탈로그 확장

- 상품 선택 목록을 **96종 / 8개 카테고리**로 확장했습니다.
- Supabase에 `public.product_catalog` 참조 테이블로 96개 상품명 및 **예시 권장가격**을 추가했습니다. 기존 판매글은 변경하지 않았습니다.
- 사용자 로그인 후 실제 등록 상품은 `products`에서 읽고, 아래 `상품 미리보기`에서는 **체험 예시**를 표시합니다. 예시를 실제 판매글로 취급하거나 예약할 수 없습니다.
- 상단에서 `체험 모드`로 전환하면 96종 샘플에 대해 매칭 흐름을 시연할 수 있습니다. 체험 결과는 서버에 저장하지 않습니다.
- 상품 등록 시 상품을 변경하면 권장가격·최저가가 임시 제안되고 사용자가 자유롭게 수정할 수 있습니다. 권장가격은 실제 판매가/시세 데이터가 아닙니다.
- 이 변경 사항은 기존 윈도우 설치 폴더에 자동 반영되지 않습니다. 새 압축파일을 풀고 교체한 뒤 개발 서버를 다시 실행해야 합니다.
- 개발 환경은 네트워크 차단으로 인해 `npm install`/`npm run build` 실행을 완료하지 못했습니다. 기존 매칭 자동 테스트 9개는 통과했습니다.
